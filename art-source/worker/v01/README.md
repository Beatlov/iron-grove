Всего **256 кадров**. Строки: **S,N,W,E,SW,SE,NW,NE**. Столбцы — время слева направо. Промежутков нет. Строки каждого листа размечены отдельно по шлему/ранцу: idle использует исходные строки 0,1,2,3,5,4,6,7; walk/carry_walk — 0,1,2,3,4,5,6,7; work — 0,1,3,2,5,4,6,7; death — 0,1,3,2,5,4,7,6. Это направление тела в начале действия: исходная гибель местами меняет направление внутри ряда; такой поворот сохранён, восемь идеально согласованных ракурсов гибели не заявляются.

## Что сделано

- Выделены отдельные персонажи по маске alpha≥128; мелкие отдельные артефакты исходного фона исключены. Изображения не обрезались на равные доли большого холста вслепую.
- На каждый полный лист выбран один коэффициент по стоящим фигурам, без растягивания отдельных поз. Корпус зарегистрирован по шлему, не по центру силуэта с инструментом/ящиком; линия земли общая для исходного ряда. Это устраняет случайный сдвиг корпуса при разной ширине инструмента.
- Для гибели сохранена фиксированная исходная сетка отсчёта ряда: падающее тело не центрируется и не увеличивается отдельно в каждом кадре. Опора метаданных остаётся той же, хотя персонаж естественно отклоняется от неё при падении.
- Площадное уменьшение затем приведение к фиксированной плоской палитре, без дизеринга. Alpha только 0/255, тёмный однопиксельный периметр, прозрачные пиксели очищены. Контактный лист увеличен nearest-neighbor.

## Ограничения и подключение

Исходные анимации сгенерированы и содержат изменения формы инструмента, конечностей и шлема между позами; техническая регистрация не превращает их в вручную прорисованную идеальную анимацию. Незначительное движение головы/конечностей внутри кадра остаётся намеренной частью поз. При малом размере часть мелких деталей потеряна. Это подготовленные нативные атласы для оценки и дальнейшего подключения, а не заявление о бесшовности каждого исходного движения.

Carry_walk содержит исходный универсальный контейнер. Нет отдельных слоёв груза/эффектов и специальных sow/mine/harvest: work пока только универсальная работа инструментом. При подключении ходьбу привязать к пройденному расстоянию (в том числе по дорогам ×2), не менять игровые таймеры по FPS. Гибель проигрывать один раз. Прогресс, здоровье, выделение и интерфейс рисовать отдельно.

Воспроизводимая обработка: из корня `python3 scripts/prepare-sprites.py` (опциональные инструменты подготовки Pillow/NumPy/SciPy; игре не нужны). Исходники не изменяются. Для проверки — `python3 scripts/check-prepared-sprites.py`. Код загрузки PNG в игре не добавлен.
